# Weekly engineering review

Use the same private registry, pause flag and shared lock as the daily cycle. Limit the review to 45 minutes. Inspect seven days of checkpoints, shipped revisions, CI failures, open issues/PRs and available analytics. Never treat proposed changes as shipped.

For each project, summarize delivery lead time, change failures, open review age and known operating cost; mark unavailable measurements unknown. For websites, assess the weekly traffic/click/scroll evidence and whether last week's hypothesis improved. For services, prioritize reliability and regression coverage before speculative features. For OSS, inspect community reports and contributor PRs without running untrusted code with credentials.

Choose at most three next priorities per project and a single next portfolio implementation task. Recommend continue/maintain/pause with reasons. Do not close contributor issues, upgrade dependencies, deploy, merge or expand the portfolio automatically. New landing-page projects are discovery candidates until their repository, visibility and permissions are verified.

Write one private weekly report and reconcile the existing backlog without duplicate issues. Request only concrete decisions. Stay quiet when there is no meaningful change. Release the lock with its token even when a run fails.
