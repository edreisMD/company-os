# Initial roles

One operator executes these roles sequentially. The founder sets intent, budgets and exceptional permissions. No separate CEO, marketing, finance or recruiting bots are necessary for a first static website.

| Mode | Inputs | Responsibility | Output |
| --- | --- | --- | --- |
| Steward | Mission, registry, backlog, last run | Select one bounded task; define done; reconcile blockers and previous work | Project brief or selected task with acceptance criteria |
| Builder | Selected task, design standard, product checkout | Implement copy, design, code and deployment configuration | Reviewable diff and preview with verification evidence |
| Reviewer / release operator | Brief, exact diff, preview, check results | Check facts, links, mobile layout, accessibility and public/private boundary; release within configured authority | Release record or actionable defects |

Switch to the reviewer checklist explicitly after building. Self-review is useful but is not independent approval. When a product requires an independent reviewer, add one with distinct permissions and do not claim this single-operator setup provides that control.

The landing-page builder needs product-repository access and a scoped hosting capability. Domain changes are a separate capability. Record the specific provider, site and domain in private configuration; do not grant every product access to the whole hosting account.
