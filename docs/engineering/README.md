# Engineering department

Role instructions live in [engineering/](../../engineering), with the root [routing skill](../../SKILL.md) selecting the right specialist. The supporting documents here explain shared operating contracts, not a second prompt system.

Discovery proposes backlog work. Prioritization starts planning. Human approval of the exact plan permits development. Code review and QA examine the exact resulting revision. CI stages the artifact; human approval precedes production. See [frontend delivery](frontend-delivery.md), [CI/CD](ci-cd.md), [analytics](analytics.md) and [project profiles](profiles.md).

Only one implementation should be active per project, with a bounded portfolio concurrency limit. Native platform permissions and private project authorization govern every external action. Role names and schedules do not confer approval authority. Keep private reports private and unknown metrics unknown.
