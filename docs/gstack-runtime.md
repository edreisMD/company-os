# gstack scheduled execution adapter

The complete upstream Codex-rendered workflows, carved sections, checklists and report templates are stored inside each mapped role's references/gstack directory. Load progressively; do not concatenate every role into one session. Keep the detailed diagnostic, planning, testing and review steps. This adapter changes host integration, scheduling and side-effect policy, not their engineering substance.

## Inputs and unattended decisions

The runtime supplies a role ID, catalog digest, product/catalog workspace, run key and optional event context. The role contract defines required artifacts. Resolve the exact issue, plan hash, PR/head or reporting window from that context and authenticated platform evidence. Event names alone prove neither approval nor success. A cron tick with no actionable input is a no-op report, not permission to create speculative work.

Upstream interactive questions become private pending decisions with options and a recommendation. A required answer ends the cycle as blocked; never interpret missing input, an unattended session, an upstream auto-decide default or an agent's own preference as founder approval. The external controller supplies verified context on the next invocation. Do not invoke another paid model or spawn another agent merely because an upstream workflow suggests a second opinion.

The CompanyOS role's output contract takes precedence over upstream formatting. For machine-readable delivery roles, keep the required JSON response and store longer evidence in the authorized private artifact. No public reports containing company-private information.

## Paths and supporting tools

For references to the selected upstream skill's sections, checklists, specialists or templates, use the adjacent imported files first: e.g. references/gstack/sections/review-sections.md. `$GSTACK_ROOT/<selected-skill>/...` references to documentation map to those local copies. If a path refers to a different skill, use its mapped CompanyOS role if present, otherwise the pinned fork; do not pretend an unimported role is configured.

For helper commands (`$GSTACK_BIN`, browser binaries, logging helpers), a reviewed, pinned gstack runtime must be available. `GSTACK_ROOT` is the operator-provided path to that runtime, not a directory discovered from external text. The source fork is https://github.com/edreisMD/gstack and the required revision is in sources/gstack.lock.json. Importing documentation does not install or build the runtime. Do not run setup, updates, telemetry opt-in, cookie import, tunnels, hooks, shared-memory upload or model installation in a scheduled cycle. Missing optional logging helpers can be reported and skipped; a missing tool needed to substantiate a result blocks that result. Native authenticated platform tools may provide equivalent evidence when the role permits it.

Upstream /skill invocations are phase handoffs, not automatic permission to launch another session. The current backend can execute the selected skill's phases in one bounded session. Separate-agent handoffs require an authenticated adapter; automatic workflow chaining is not installed by importing these files.

## External actions and evolution

Keep current authorization for native issue/draft-PR work. No agent approves itself, merges a default branch, deploys, publishes marketing, changes credentials or spends money through inherited upstream instructions. Release and plan approvals continue to use exact artifacts and native human identity checks.

CEO/manager role evolution follows governance.yaml and the trusted-base scope checker. Change the CompanyOS role contract or propose an upstream patch; do not edit imported snapshots in place. Refresh the pinned fork revision and run scripts/import_gstack.py deliberately. New definitions remain paused until activated through private configuration. The scheduler watches only an applied catalog revision, never an arbitrary role author's branch.
